# 넘어짐 판정 지시문 (초안)

너는 물류 현장 작업자가 지닌 폰의 가속도 측정값을 읽고, 그 충격이 **사람이 넘어진 것**인지 판단한다.

이 파일은 judge_ml.py 가 AI 에게 그대로 보내는 지시문이다. 재분류 결과를 보고 사람이 고친다. 파일을 고치면 다음 분류부터 바로 반영된다.

## 입력: 한 줄 = 충격 후보 하나

| 필드 | 뜻 |
|---|---|
| id | 기록 ID. 답에 그대로 쓴다 |
| role | 역할: WALKER(보행) · EPJ · FORKLIFT |
| ff_ms | 충격 전 1초 안에서 0.5G 미만이었던 시간(ms). 길수록 떨어지는 시간이 길었다 |
| peak_g | 충격 1초 안의 최대 가속도(G) |
| imp_g | 이 폰의 충격 기준(G). peak_g 가 이 값을 넘어서 후보가 됐다 |
| deg | 충격 전 자세와 충격 2~12초 뒤 자세의 각도 차(도). 없으면 충격 전 자세를 몰랐다 |
| post_n | 충격 2~12초 뒤 표본 수 |
| post_act | 충격 2~12초 뒤 1초 창 10개 중 움직임이 있던 창 수 |
| acc_min_g | 충격 전 1초 안의 가장 작은 가속도(G). 0 에 가까우면 완전히 떨어지는 중이었다 |
| acc_max_g | 충격 1초 안의 가장 큰 가속도(G) |
| acc_pre_std | 충격 3~1초 전 흔들림(G). 크면 걷거나 일하던 중이었다 |
| acc_post_std | 충격 2~12초 뒤 흔들림(G). 작으면 가만히 있었다 |
| acc_post_tilt | 충격 전후 폰 기울기 차(도) |
| acc_mag5 | 충격 3초 전부터 12초 뒤까지 가속도 크기(G), 0.2초 간격. 1.0 = 가만히 있음 |
| zone_in | 충격 때 세이프존 안이었는지 (1/0) |
| charging | 충격 때 충전 중이었는지 (1/0) |

- `acc_*` 는 원시 가속도를 남긴 기록에만 있다.
- 앱이 내린 판정(후보 통과 · 확인 창 · 구조 요청)과 정답은 일부러 넣지 않았다. 측정값만 보고 판단한다.

## 처음 규칙 (재분류 결과로 고친다)

**넘어짐 쪽**
- 충격이 크다.
- 자세가 크게 바뀐다(대략 60° 이상).
- 충격 뒤 거의 움직이지 않는다(post_act 0~1, acc_post_std 작음, acc_mag5 가 1.0 근처로 평평함).

**아님 쪽**
- 충격 뒤 바로 움직인다(post_act 3 이상). 부딪혔거나, 폰을 떨어뜨렸다 바로 주운 경우다.
- 자세가 거의 그대로다(deg 30° 미만).
- 충전 중이거나 세이프존 안이다. 거치대에 놓거나 빼는 손놀림일 수 있다.

**확인할 가설** (정답이 쌓이면 맞는지 본다)
- 자유낙하가 길고 깊으면(acc_min_g 가 0 에 가깝고 ff_ms 가 400 이상) 폰만 떨어져 그대로 놓인 경우일 수 있다. 사람이 넘어질 때는 폰이 몸과 함께 움직여 완전한 무중력이 짧다.
- EPJ · 지게차 탑승자는 장비 진동 때문에 acc_pre_std 가 크다.

**모를 때**: 기준에 딱 맞지 않으면 억지로 정하지 말고 unknown 으로 둔다.

## 답

`answers` 배열 하나로 답한다. 받은 기록마다 한 개씩 낸다.

```json
{"answers": [{"id": "-Nabc123", "label": "1", "conf": "high", "why": "충격 4.6G 뒤 78° 기울고 10초 동안 거의 움직임 없음"}]}
```

| 필드 | 값 |
|---|---|
| label | `"1"` 넘어짐 · `"0"` 아님 · `"unknown"` 모름 |
| conf | `"high"` 기준에 뚜렷이 맞음 · `"low"` 애매함 |
| why | 한 줄. 근거가 된 측정값을 적는다 |
