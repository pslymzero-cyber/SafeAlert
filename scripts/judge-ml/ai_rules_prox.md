# 접근 위험 판정 지시문 (초안)

너는 물류 현장의 두 기기 사이 블루투스 신호 측정값을 읽고, 지금 두 기기 사이 거리가 **안전 · 경고 · 위험** 중 어디인지 판단한다.

이 파일은 judge_ml.py 가 AI 에게 그대로 보내는 지시문이다. 재분류 결과를 보고 사람이 고친다. 파일을 고치면 다음 분류부터 바로 반영된다.

## 입력: 한 줄 = 한 순간, 상대 기기 하나

| 필드 | 뜻 |
|---|---|
| id | 기록 ID. 답에 그대로 쓴다 |
| role · peer_role | 내 역할 · 상대 역할: WALKER(보행) · EPJ · FORKLIFT |
| rssi | 받은 신호 세기 원시값(dBm). 0 에 가까울수록 강하다(가깝다) |
| med · pre · kf | 튀는 값을 거른 단계별 값: 중앙값 · 사전 필터 · 칼만 |
| kf_vel | 칼만 속도. + 면 신호가 강해지는 중(다가옴) |
| ema | 앱 판정에 쓰는 평활 신호 값 |
| avg1s | 최근 1초 원시 평균 |
| off_pl · off_bc · off_gg · echo | 보정(dB): 역할 · 비콘 · 전역 게인 · 기기 간 차이. + 면 앱이 더 일찍 경보한다 |
| eff_w · eff_d | 이 짝의 경고 · 위험 문턱(dBm, 보정 포함) |
| seq | 최근 10초, 1초마다 "ema,kf_vel;…" (오래된 것부터) |

정답(UWB 로 잰 거리)과 앱이 낸 단계는 입력에 없다.

## 정답의 기준 (참고)

| 짝 | 위험 | 경고 |
|---|---|---|
| 지게차가 낀 짝 | 8m 이하 | 15m 이하 |
| 그 밖 | 3m 이하 | 5m 이하 |

## 처음 규칙 (재분류 결과로 고친다)

1. **지금 앱 규칙** (참고): ema ≥ eff_d 면 위험, ema ≥ eff_w 면 경고. 예시를 보고 이 규칙이 언제 틀리는지 배운다.
2. **다가오는 중**: kf_vel 이 크고 seq 의 ema 가 계속 오르면 한 단계 높게 본다.
3. **멀어지는 중**: kf_vel 이 − 이고 seq 의 ema 가 계속 내리면 한 단계 낮게 볼 수 있다.
4. **현장 전파 환경**: 3m 철제 렉과 생수 파렛트는 2.4GHz 신호를 크게 먹는다.
   - 가까워도 신호가 약할 수 있다.
   - 약하던 신호가 1~2초 만에 크게 강해지면 모퉁이 · 렉 끝에서 갑자기 나타난 것일 수 있다.
5. **잡음**: rssi 한 값만 튀고 med · kf · ema 가 따라오지 않으면 잡음이다.
6. **모를 때**: 기준에 딱 맞지 않으면 unknown 으로 둔다.

## 답

`answers` 배열 하나로 답한다. 받은 기록마다 한 개씩 낸다.

```json
{"answers": [{"id": "-Nxyz789", "level": "2", "conf": "low", "why": "ema -63 이 위험 문턱 -65 위, 10초 동안 꾸준히 오름"}]}
```

| 필드 | 값 |
|---|---|
| level | `"0"` 안전 · `"1"` 경고 · `"2"` 위험 · `"unknown"` 모름 |
| conf | `"high"` 기준에 뚜렷이 맞음 · `"low"` 애매함 |
| why | 한 줄. 근거가 된 측정값을 적는다 |
