## 선행 항목 E — echo_calib 전역 규칙 누락 (실측 확인됨)

- 실측 2026-09-11 (무인증 GET):
  `/version.json` 200, `/TESTSITE/echo_calib.json` 200, **`/echo_calib.json` 401**.
- 원인: v1.1.85 에서 echo_calib 를 `/{site}/echo_calib/{id}` 에서 전역 `/echo_calib/{id}` 로 옮겼는데,
  `database.rules.json` 에는 `$site` 아래(32-37행)에만 echo_calib 규칙이 있다.
  최상위 `echo_calib` 는 `$site` 와일드카드에 걸리고 그 아래 `$id` 는 정의된 자식(version/alerts/beacon_share/echo_calib/uwb_probe)이 아니라 거부된다.
  규칙이 auth 를 보지 않으므로 앱(익명 로그인)도 동일하게 거부된다.
- 영향 (추정, 착수 시 로그로 확인): v1.1.85 이후 에코 보정 업로드 실패, 전역 읽기 실패. 구 경로 폴백 파싱만 살아 있음.
- 수정: 최상위에 `$site` 아래 echo_calib 블록과 같은 모양의 `"echo_calib"` 형제 추가 (이름 있는 키가 `$site` 보다 우선).
- 배포: 규칙은 CI 가 정식 태그 때만 PUT 한다. 두 방법 중 사용자 선택
  1. 즉시: 저장소 파일 수정 + 커밋, 사용자가 콘솔 규칙 탭에 같은 내용 게시. (저장소도 고쳐야 다음 태그가 되돌리지 않는다)
  2. v1.1.87 태그에 포함 (재설치 전 기기도 즉시 복구되므로 무해).
- 검증: `/echo_calib.json?shallow=true` 200, 콘솔 `echo_calib/{id}` 노드 `ver` 갱신.
- Phase D 에서 이 최상위 블록도 auth != null 로 함께 잠근다.

## Phase A — 사람 작업 (Phase B 착수 전 완료 확인)

A1. 릴리스 키스토어 생성 (비밀번호는 keytool 이 대화형으로 묻는다)

```
keytool -genkeypair -v -storetype PKCS12 -keystore safealert-release.p12 -alias safealert -keyalg RSA -keysize 4096 -validity 10000
```

- 저장소 밖에 보관, 오프라인 백업 2곳 이상. 분실 = 이후 업데이트 영구 불가(전 기기 재설치 반복).
- 지문 확인: `keytool -list -v -keystore safealert-release.p12 -alias safealert`. SHA-256/SHA-1 지문(공개값)만 Claude 에 전달.

A2. GitHub Secrets 등록 (사용자 직접)

- `base64 -w0 safealert-release.p12 | gh secret set RELEASE_KEYSTORE --repo pslymzero-cyber/SafeAlert`
- `gh secret set RELEASE_STORE_PASSWORD --repo pslymzero-cyber/SafeAlert` (프롬프트에 입력)
- 같은 방식으로 `RELEASE_KEY_ALIAS`, `RELEASE_KEY_PASSWORD`
- `DEBUG_KEYSTORE` 는 삭제하지 않는다.

A3. Firebase / GCP 콘솔 점검

- Authentication > Sign-in method > 익명 = 사용 설정 확인.
- GCP > API 및 서비스 > 사용자 인증 정보 > google-services.json 의 API 키: "Android 앱" 제한이 있으면 새 SHA-1 + 패키지명 추가(기존 debug SHA-1 은 전환 완료까지 유지). 제한 없으면 할 일 없음.
- Firebase 프로젝트 설정 > 앱 > SHA 지문에 새 SHA-1/SHA-256 추가 (필수 아님, 무해).

A4. 기기별 재설치 전 기록표

| 기기 | 표시 이름(=device_id) | 역할 | 사업장 코드 | 비콘 공유세트 이름 | 개발자 설정 변경값 |
|---|---|---|---|---|---|

- device_id 는 표시 이름이다. 비워 두면 `MainActivity.kt:617` `myId()` 가 `SA-xxxxxxxx` 를 새로 발급해 서버 이력이 끊긴다.

### B2. device_id 입력 검증 (R-07)

- 유일 입력점: `MainActivity.kt:793-796 saveDisplayName()` (etDisplayName, prefs `display_name`).
- 흐름: `MainActivity.kt:616` / `:742` 에서 display_name 을 읽어 BLE 송출 ID 로 사용, BleService `saveRunningMode` (BleService.kt:721-727) 가 `device_id` 로 저장.
- 규칙은 거부목록 방식 (지금 쓰는 한글 이름을 깨지 않기 위해). trim 후
  - 빈 문자열 허용 (= 자동 SA- ID, 기존 동작)
  - Firebase 키 금지문자 `. # $ [ ] /` 와 제어문자 포함 시 거부
  - 길이 상한 초과 시 거부. 상한 값은 착수 시 `activity_main.xml` 의 etDisplayName maxLength 와 BleAdvertiser.kt 의 ID 적재 방식을 grep 해서 결정 (확인 전 임의 숫자 금지)
- 거부 시 저장하지 않고 Toast + 입력칸을 이전 저장값으로 되돌림. 조용한 치환 금지.
- 순수 함수 `isValidDeviceId(s: String): Boolean` 를 `FirebaseManager.kt:81 sanitizeKey` 옆에 두고 단위테스트 1개:
  허용 `김영생`, `나인`, `SA-1A2B3C4D`, `wf_11` / 거부 `a.b`, `a/b`, `a#b`, `$`, `a[b]`, 제어문자, 상한 초과.
- 재설치로 prefs 가 비므로 기존 저장값 마이그레이션 불필요.
- 사업장 코드는 v1.1.77 setter 가 이미 `[A-Z0-9_-]` 로 정규화. 손대지 않는다.

### B3. 업데이트 APK 무결성 (R-04, B6 과 세트)

- `UpdateManager.kt:24-26` UpdateInfo 에 `apkSha256: String` 추가, `:38-41` 에서 `snap.child("apk_sha256")` 읽기.
- `MainActivity.kt:937` `downloadAndInstall(this, info.apkUrl)` 에 해시 인자 전달.
- `UpdateManager.kt:84-86` STATUS_SUCCESSFUL 분기의 `installApk` 직전에 검증:
  파일 SHA-256 (MessageDigest, 스트리밍) 소문자 hex 와 비교. 불일치 또는 기대 해시 공란이면 파일 삭제, 설치 거부, Toast, Log.e. (fail-closed)
- 순수 함수 `sha256Hex(InputStream): String` + `hashMatches(expected, actual): Boolean` (대소문자·앞뒤공백 무시, 공란은 false) 분리, 단위테스트 1개.
- 구버전(<=1.1.86) 기기는 이 검증이 없고 서명이 달라 어차피 설치 실패. Phase C 재설치로만 넘어온다.
