# SafeAlert — CouSolve Idea Contest 제출본

사내 **CouSolve Idea Contest 제출 양식**(16장)에 채운 실제 출품본이다.
`../cousolve/` 의 Report 판, `../company_form/` 의 LFP 판과 같은 내용을 세 번째 골격에 옮긴 것이며,
셋은 서로 독립이다. 이 판이 **콘테스트 제출용**이다.

| 장 | 절 | 내용 |
|----|----|------|
| 1 | 표지 | 주제 · Region/FC · Nickname |
| 2 | 01. 결론 | 문제 / 해결 / 확인 세 줄 — 마지막 줄에 저장소 주소와 최신 릴리스 |
| 3 | 01. Summary | Background · Solution · Result (커버리지 막대 + 조우 추정 카드) |

제출본에 그대로 두면 결번처럼 보인다. 나머지 14장은 순서 · 구조를 그대로 따랐다.

## 양식을 다룰 때 걸린 것

- **라벨 칩이 상자 왼쪽 위를 덮는다.** 글을 그냥 넣으면 칩과 겹친다.
  `_contest.py` 의 `TOPCHIP = 0.40` 을 윗 여백으로 준다 (`fill(..., top=C.TOPCHIP)`).
- **본문 상자는 그룹 도형**이다. 라벨 칩 글자로 그룹을 찾아 큰 쪽을 집는다 (`body_of`).
- **5Why 표는 Why 하나에 두 줄**이다. 라벨 칸이 `rowSpan=2` — 위 줄에 질문, 아래 줄에 답.
  `Most likely Causes` · `Root Causes` 는 표 밖 텍스트박스라 따로 채운다.
- **글꼴은 맑은 고딕, 강조색은 `#053866`** (양식의 활성 탭 색). 그대로 따랐다.
- `ppt/revisionInfo.xml` 스키마 경고는 **양식 원본에 이미 있는 것**이다
  (`validate.py --original` 로 비교하면 통과).

## 전제 정정 (2026.09) — 우리 센터에는 I-PAS 가 없다

처음 원고는 **현행 장비가 I-PAS 라는 전제**로 쓰여 있었다. 사실이 아니다.
I-PAS 는 사내 다른 조직이 도입해 쓰는 것이고, **WF11 에는 접근을 감지하는 장치가 아예 없다.**

이 정정으로 이야기가 더 단순하고 강해진다.

| 잘못된 원고 | 고친 것 |
|-------------|---------|
| "I-PAS 가 못 덮는 조합을 앱이 메운다" | **"감지 장치가 하나도 없다. 앱이 처음으로 감지를 시작한다"** — 현재 감지되는 장비 `0대` |
| I-PAS 를 현행 비교 대상으로 | **벤치마크(8장)로 이동** — 사내 타 조직 도입 사례로 명시하고, 도입 비용 331만원도 여기서 비교 |
| 비용을 '절감액이 아니다' 라고 방어만 함 | 벤치마크 표에 **도입 비용 열**을 넣어 정면으로 비교 — I-PAS 331만원 / 이 앱 0원 |
| 5Why 뿌리가 "태그 구매 수량" | **"접근 감지를 '장비를 사는 일' 로만 봐 왔고, 예산이 서지 않으면 대책이 0 인 상태가 유지됐다"** |
| Tradeoffs 2번이 "I-PAS EOD 를 그대로 두고" | **"지금은 자동 정지도 경보도 둘 다 없다. 장비 없이 할 수 있는 쪽부터 넣었다"** |

## 용어 — 심사위원이 읽는 글로

작성자끼리 쓰던 말을 걷어냈다. 첫 장에서 막히면 뒤를 안 본다.

| 고치기 전 | 고친 뒤 |
|-----------|---------|
| 덮는다 / 커버한다 | 감지한다 · 경보가 울린다 · 감지 대상이 된다 |
| 접근 조우 · 조우 | 가까워진 횟수 · 접근 |
| 감지 쌍 · 21쌍 | 서로 감지되는 짝 · 21가지 |
| 판정 반경 · 판정 로직 | 경보 거리 · 경보 계산 |
| 미발령 / 오발령 | 경보가 안 울렸다 / 쓸데없이 울렸다 |
| 세이프존 | 안전 구역 |
| 골든 테스트 · CI 회귀 게이트 | 자동 검사 |
| Phase 1~5 · 로드맵 | 1~5단계 · 앞으로의 개선 계획 |
| 단말 · 지급 단말 | 폰 · 업무용 스마트폰 |
| 하드웨어 · 인프라 | 장비 |
| 리소스 배정 · 정식 과제 등록 | (요청은 실행 계획의 `협조` 행으로) |

**01. 결론 장은 통째로 다시 썼다.** 심사위원이 가장 먼저 보는 장이므로,
문제 → 해결 → 확인 세 줄이 각각 한 문장으로 읽히게 했다.

세 번째 줄은 처음에 "이미 쓰고 있습니다" 라는 말뿐이었다. 그건 증거가 아니라 주장이다.
**저장소 주소와 최신 릴리스 버전**으로 바꿨다 — 심사위원이 직접 열어서 확인할 수 있는 것이
증거다. 버전은 `LATEST` 상수 한 곳에서 관리하고, 릴리스가 올라가면 그 값만 고친다.

## 숫자 원칙

실측이 없는 칸은 비우지 않고 추정치를 넣되, **자료 전체에서 밑줄은 '실측 아님' 한 가지 뜻만** 갖는다.

| 항목 | 값 | 근거 |
|------|----|------|
| 감지 쌍 | 21쌍 | 차량 4 + 상시 3 = 7대, C(7,2) — **실측 구성** |
| 쌍당 경고 조우 | <u>0.5회/시간</u> | 보수적 가정 — **이 자료의 유일한 가정값** |
| 경고 조우 | <u>교대당 95회</u> | 21 × 9시간 × 0.5 = 94.5 |
| 위험 전이율 | <u>0.28</u> | 반경 비의 제곱 (8m / 15m)² |
| 위험 조우 | <u>교대당 27회</u> | 95 × 0.28 = 26.6 |
| 오발령 | <u>교대당 3회 미만</u> | 자동 음소거(v1.1.61) · 이탈 억제(v1.1.51) 적용 후 |
| 체감 만족도 | <u>7.0 / 10</u> | 요구 4건 전량 반영 · 3개 센터 사용 지속 |

가정값을 하나로 몰아 뒀다. 실측 한 번이면 나머지가 전부 교체된다 (`../cousolve/analyze_alerts.py`).
슬라이드에 적힌 식과 표시 자릿수가 어긋나지 않게, 계산도 표시하는 자릿수로 한다 (`_half_up`).

그 밖에 지킨 선:

- **비용은 벤치마크(8장)에서 비교한다.** 우리 센터 규모(지게차 4대 · 상시 3명)로 장비를 갖추면
  331만원(차량 태그 52.5만×4 + 자동정지장치 22만×4 + 보행자 태그 11만×3), 이 앱은 0원.
  사내 타 조직 도입 단가 기준이며 '절감액' 이 아니라 '같은 목적을 장비로 할 때의 금액' 이다.
  3장 막대는 사람이 늘 때 감지되는 짝의 수 — 장비는 선형, 앱은 제곱 (팔레트 검증 6/6 통과).
- **「미발령 0건」은 지표에서 뺐다.** 미발령은 정의상 관측되지 않는다. 뺐다는 사실을 12장에 적었다.
- **앱은 장비를 자동으로 세우지 못한다.** 3 · 7 · 8 · 9장에 네 번 적혀 있다.
  '자동으로 멈추기' 가 '사람에게 알리기' 보다 확실하다는 것도 7장에 그대로 적었다 —
  다만 지금 우리 센터에는 둘 다 없고, 장비 없이 할 수 있는 쪽부터 넣었다는 것이 이 제안의 논지다.
- **사고 건수 · 셧다운 건수는 회사 데이터로 존재하지 않는다.** 추정치를 만들지 않고 지표에서 제외했다.
- 외부 벤치마크의 '아차사고 감소 · ROI 3~6개월' 은 벤더 주장이라 인용하지 않았다.
