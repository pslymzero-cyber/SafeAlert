## 1. 선조치 3건 (자체 진행)

심사 요청과 별개로 먼저 처리한다. 완료 시 개인정보 처리 신고 철회와
데이터 분류 하향(Confidential → Internal)을 함께 요청한다.

### [SA-1] 기기 표시명을 선택식 장비 ID 로 전환

| 항목 | 내용 |
|---|---|
| 목표 | 개인 식별 정보가 저장될 **입력 수단 자체를 화면에서 없앤다** |
| 조치 | 자유 입력 폐지. 장비 종류 드롭다운 + 번호 드롭다운(1~99) 선택식으로 전환. 역할 카드는 `장비 작업자` 하나로 통합 |
| 송출 ID | `종류코드-번호` 5바이트 고정 — `CB-01`, `RT-07`, `HR-99` |
| 경보 로그 | `센터명-장비ID` — `WF11-CB-01` |
| 대상 | `PitType`(신규) / `FirebaseManager` / `MainActivity` / `dialog_pit_select.xml`(신규) / `activity_main.xml` |
| 적용 | v1.1.89 (versionCode 145) |
| 상태 | [x] 완료 — v1.1.89 |

**형식 검증이 아니라 입력 수단 제거다.** 초안은 자유 입력에 정규식을 거는 방식이었다.
그 방식은 규칙이 아무리 촘촘해도 우회 여지가 남고(`PARKYOUNGSU1`), 현장에서는 장갑 낀
손으로 12자를 치는 부담이 생긴다. 선택식은 두 문제를 동시에 없앤다 — 키보드가 뜨지
않으므로 사람 이름이 들어올 경로가 **화면에 존재하지 않는다.**

| 장비 종류 | 코드 | 경보 Category |
|---|---|---|
| C/B (카운터밸런스) | `CB` | FORKLIFT |
| 리치 | `RT` | FORKLIFT |
| 하이리치 | `HR` | FORKLIFT |
| 오더피커 | `OP` | FORKLIFT |
| 스태커 | `ST` | FORKLIFT |
| 견인차 (토우) | `TT` | FORKLIFT |
| EPJ (전동 파렛트 잭) | `EP` | EPJ |
| 워키 (워키 스태커) | `WK` | EPJ |

**역할을 고르지 않는다. 장비를 고르면 역할이 따라온다.** 기존에는 `지게차` / `EPJ`
카드로 역할을 먼저 고르고 장비를 또 골랐다. 그러면 지게차 카드를 누른 사람이 EPJ 를
고르는 불일치가 가능하고, 경보 반경이 실제 장비와 어긋난다. 카드를 `장비 작업자`
하나로 합치고, 선택한 `PitType.category` 가 그대로 경보 Category 가 되게 했다.

| 카드 | 동작 |
|---|---|
| 보행자 | 장비 선택 없음 → 자동 ID |
| 장비 작업자 | 장비 선택 팝업(8종 × 1~99) → 고른 장비의 Category 로 시작 |

`card_role_epj` 는 레이아웃에서 `visibility="gone"` 이다. 되살리지 않고 EPJ·워키를
장비 목록에 넣었다 — 카드를 늘리면 같은 불일치가 다시 생긴다.

장비 선택은 시작할 때마다 거친다. 교대마다 타는 장비가 바뀌는데 직전 값으로 그냥
시작하면 경보 로그가 다른 장비를 가리킨다. 직전 선택이 복원돼 있어 확인 1탭이면
끝난다. 역할 전환(`performSwitchRole`)에서 장비로 넘어갈 때도 같은 팝업을 거친다.

**BLE 에 센터명을 싣지 않는 이유.** 송출 ID 는 5바이트 고정이라 15바이트 예산 중
10바이트가 에코 데이터 쪽에 남는다. 센터명은 12자까지 허용돼 함께 실으면 예산을
넘긴다. 대신 `FirebaseManager.saveAlert` 가 저장 시점에 센터명을 붙여
`WF11-CB-01` 로 남긴다 — 경로(`alerts/{site}/…`)와 `site` 필드가 이미 같은 전제
위에 서 있다. BLE 로 만난 상대는 물리적으로 같은 센터 안에 있다.

**기존 값 이행.** `display_name` 만 지우는 것으로는 부족하다.
`BleService.saveRunningMode()` 가 실행 시 `device_id` 를 표시 이름으로 덮어쓰기
때문에, 옛 이름이 자동 ID 자리에 그대로 남아 계속 송출된다. 두 키를 함께 본다.

| 기존 값 | 이행 동작 | 경보 영향 |
|---|---|---|
| `display_name` 이 `CB-01` 형식 | 유지 | 없음 |
| `display_name` 이 사람 이름 | 삭제 + 1회 안내 팝업 | 없음 — 자동 ID 로 송출 |
| `device_id` 가 장비 ID / 자동 ID | 유지 | 없음 |
| `device_id` 가 사람 이름 | 자동 ID 신규 발급으로 **교체** | 없음 |

`device_id` 를 지우지 않고 교체하는 이유는 `BleService.onStartCommand()` 의
`START_STICKY` 복원 경로가 키 부재 시 `"SA-DEFAULT"` 를 싣기 때문이다. 지우기만
하면 이행된 기기 전부가 같은 ID 로 송출돼 피어 식별이 무너진다.

이행은 `MainActivity.onCreate()` 에서 1회 수행하고, 어떤 분기에서도 서비스 시작이나
경보 판정을 막지 않는다. 장비 선택 팝업을 취소해도 시작 전 상태라 동작 중인 경보에
영향이 없다.

**로컬 에코 보정 데이터는 영향받지 않는다.** 보정값은 모델쌍 단위로 로컬 prefs 에
저장되며 `device_id` 는 업로더 태그로만 쓰인다(`CalibrationEngine.persistEchoAll`).

**번호 상한 99.** 한 센터에 같은 종류가 100대를 넘지 않는다는 현장 확인을 거쳤다.
2자리 고정이라 송출 ID 가 5바이트로 맞는다. 3자리로 늘리면 이미 배포된 기기의 파싱과
어긋나므로 상한 변경은 전 기기 동시 배포가 전제다.

**입력 부담.** 드롭다운은 장갑 낀 손과 창고 조명을 전제로 항목 높이 64dp · 글자
22sp 로 키웠다. 라벨 QR(페이로드가 장비번호 원문 `8FB25-40604`)을 쓰는 방식은
채택하지 않았다 — 스마트폰은 `CAMERA` 권한이 필요해 제출한 심사 내용이 바뀌고,
선택식은 권한 추가 없이 같은 목표를 달성한다.

## 2. 검토 요청 4건 (선조치로 해소되지 않음)

| # | 항목 | 자체 조치 가능 여부 |
|---|---|---|
| SR-1 | 소스 저장소가 개발자 개인 GitHub 공개 저장소에 위치 | 불가 — 배포 구조 문제 |
| SR-2 | GitHub Releases APK를 앱이 직접 내려받아 자체 설치 (`REQUEST_INSTALL_PACKAGES`) | 불가 — 배포 구조 문제 |
| SR-3 | 설정 접근 인증 값의 빌드 시 주입 전환 | 가능 — BuildConfig + CI Secrets |
| SR-4 | 릴리스 빌드 난독화 적용 | 가능 — 적용 후 회귀 테스트 |

### SR-3 조치 방향

입력 자릿수와 동선은 유지한다. 짧은 입력은 장갑 착용 상태에서 즉시
입력·적용·검증하기 위한 운영상 선택이며, 임계값을 v1.1.77~79에서 일반
화면에서 잠근 뒤 개발자 계층으로 옮긴 구조와 연결된다. 값을 소스에서
분리하는 것만으로 해소되며 현장 운영에 영향이 없다.

## 3. 향후 계획 — PDA 이식

현장 PDA(물류 핸디 터미널)로의 이식을 계획한다. 동일 APK를 사용하며 코드
변경은 없으나, 하드웨어·운용 환경이 달라 착수 전 검증과 보안팀 의견이 필요하다.
Security Review 신청 시 "개발 전 보안팀 의견 청취" 항목으로 함께 요청했다.

| # | 검증 항목 | 내용 |
|---|---|---|
| P-1 | 신호 특성 재검증 | BLE 칩셋이 다르면 동일 거리에서도 RSSI가 달라진다. 본 앱은 `Build.MODEL` 기준 모델쌍 단위로 편차를 학습해 보정하므로, PDA 모델 투입 시 보정값을 새로 축적해야 하며 임계값 재조정이 필요할 수 있다. 현장 실측 검증 예정 |
| P-2 | MDM 배포 | PDA는 MDM으로 앱 설치가 통제되는 것이 일반적이라 자체 업데이터가 동작하지 않을 가능성이 높다. 사내 앱 배포 채널이 사실상 전제 조건이 된다 (SR-2와 직결) |
| P-3 | 공용 단말 | 작업자가 교대로 공유하므로 표시명과 개인의 1:1 대응이 성립하지 않는다. SA-1과 결합 시 개인 식별 가능성이 더 낮아지나, 경보 이력의 개별 작업자 추적은 불가해진다 |
| P-4 | 경보 인지성 | 스피커·진동 모터 사양이 달라 현장 소음 환경에서 인지성 확인이 필요하다. 안전 기능 실효성에 직결 |

기능 자체는 변경되지 않는다. PDA는 UWB 미탑재 기기로 RSSI 단독 판정으로
동작하며, 이는 현재도 UWB 미지원 기기에서 동작하는 방식과 같다.

## 4. 중장기 방향

SR-1, SR-2의 근본 해결책은 사내 이관이다. 금번 심사에서는 방향성 의견만
받고, 승인은 별도 과제로 상신한다.

| 자산 | 현재 | 이관 후 |
|---|---|---|
| 소스 저장소 | 개인 GitHub (공개) | 사내 GitHub |
| CI | GitHub Actions | 사내 CI |
| APK 배포 | GitHub Releases + 자체 업데이터 | 사내 앱 배포 채널 |
| 백엔드 | Firebase RTDB (us-central1) | 사내 인프라 — 데이터 국외 소재 이슈 동시 해소 |
| 서명 키 | GitHub Secrets | 사내 키 관리 |

이관 완료 시 자체 업데이터와 `REQUEST_INSTALL_PACKAGES` 권한을 제거한다.
