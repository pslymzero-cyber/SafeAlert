- 심사 경로: ONESEC > Security Review > Request (유형: 신규 In-House 애플리케이션 개발)

## 1. 선조치 3건 (자체 진행)

심사 요청과 별개로 먼저 처리한다. 완료 시 개인정보 처리 신고 철회와
데이터 분류 하향(Confidential → Internal)을 함께 요청한다.

### [SA-1] 기기 표시명을 장비번호로 제한

| 항목 | 내용 |
|---|---|
| 목표 | 저장 값을 자산 식별자로 한정해 개인 식별 정보 유입 경로를 없앤다 |
| 조치 | 입력을 현장 장비번호 표기로 제한. 대문자 영문·숫자·하이픈만, 영문과 숫자 각 1자 이상, 3~15자. 소문자 입력은 대문자로 정규화 |
| 현장 표기 | 지게차 C/B `8FB25-40604`·`8FB25-40577` / 리치 `8FBR18-20427`·`8FBR18-20432` (최장 12자) |
| 대상 | `FirebaseManager.isValidDeviceId()` / `MainActivity` 입력·이행 / `activity_main.xml` |
| 효과 | 개인 식별 정보 저장 경로를 코드 수준에서 차단 |
| 적용 | v1.1.89 (versionCode 145) |
| 비고 | 전 현장 기기 업데이트 필요. ASCII 최대 7바이트로 BLE 15바이트 제한을 구조적으로 넘길 수 없음 |
| 상태 | [x] 완료 — v1.1.89 |

**저장 경로 2개를 함께 정리한다.** `display_name`(사용자 입력)만 지우면 부족하다.
`BleService.saveRunningMode()` 가 실행 시 `device_id` 를 표시 이름으로 덮어쓰기 때문에,
옛 이름이 자동 ID 자리에 그대로 남아 계속 송출된다. 두 키를 모두 검사한다.

| 기존 값 | 이행 동작 | 경보 영향 |
|---|---|---|
| `display_name` 이 장비번호 | 대문자로만 정규화 | 없음 |
| `display_name` 이 사람 이름 | 삭제 + 1회 안내 팝업 | 없음 — 자동 ID 로 송출 |
| `device_id` 가 장비번호 / 자동 ID | 유지 | 없음 |
| `device_id` 가 사람 이름 | 자동 ID 신규 발급으로 교체 | 없음 |

`device_id` 를 지우지 않고 **교체**하는 이유는 `BleService.onStartCommand()` 의
`START_STICKY` 복원 경로가 키 부재 시 `"SA-DEFAULT"` 를 싣기 때문이다.
지우기만 하면 이행된 기기 전부가 같은 ID 로 송출돼 피어 식별이 무너진다.

이행은 `MainActivity.onCreate()` 에서 1회 수행하고, 어떤 분기에서도 서비스 시작이나
경보 판정을 막지 않는다. 형식 위반 입력은 저장만 거부하고 직전 값으로 되돌리므로
시작 게이트(`requireSiteCode`)는 그대로 통과한다.

**로컬 에코 보정 데이터는 영향받지 않는다.** 보정값은 모델쌍 단위로 로컬 prefs 에
저장되며 `device_id` 는 업로더 태그로만 쓰인다(`CalibrationEngine.persistEchoAll`).

**형식을 장비번호 표기 그대로 잡은 이유.** 초안은 `^[A-Z]{2,4}[0-9]{1,3}$`(예: `EPJ03`)
였으나 현장 라벨 실물이 `8FB25-40604`·`8FBR18-20427` 형태여서 전 장비가 거부된다.
쓸 수 없는 규칙은 현장에서 되돌려지므로, 문자집합과 구성 조건으로 경계를 잡았다.

| 조건 | 차단 대상 |
|---|---|
| 한글·공백·특수문자 배제 | `김영생`, `KIM YS1` — 실제 유입되던 개인 식별 정보 |
| 숫자 1자 이상 필수 | `KIM`, `PARK` — 영문 이름 |
| 영문 1자 이상 필수 | `01012345678` — 휴대폰 번호 |
| 3~15자 | 과다 입력. ASCII 전용이라 15자 = 15바이트 = BLE 송출 상한 |

자동 발급 ID 는 `^SA-[0-9A-F]{8}$` 로 따로 판정한다. UUID 앞 8자가 전부 `A`~`F` 로
나오면(약 0.08%) 숫자가 없어 장비번호 규칙에 걸리고, 이행이 매 실행마다 ID 를 새로
발급하는 무한 교체에 빠지기 때문이다. 난수 20만 건으로 이 경로를 확인했다.

**입력 수단 — 수기 타이핑이 전제가 아니다.** 장비 라벨에 이미 QR 이 붙어 있고
페이로드는 장비번호 원문이다(`8FB25-40604`, `8FB25-40577`, `8FBR18-20427` 디코딩 확인).
URL·JSON 래핑이 없어 스캔값이 그대로 입력 필드에 들어온다.

| 단말 | 입력 수단 | 앱 변경 |
|---|---|---|
| PDA (지브라·포인트모바일 등) | 하드웨어 스캐너 — 스캔값을 키보드 입력으로 던진다 | 없음. 입력 필드에 포커스만 있으면 된다 |
| 업무용 스마트폰 | 카메라 QR 스캔 | 필요 — `CAMERA` 권한 + 스캔 라이브러리 |
| 공용 | 수기 입력 | 현행. 실시간 형식 검증이 오타를 즉시 표시 |

스캐너는 스캔값 끝에 Enter/Tab 을 붙이는 경우가 많다. 이 제어문자가 필드로 들어와
값을 깨뜨리지 않도록 입력 필터에서 걸러낸다(`MainActivity.onCreate`).

**카메라 스캔은 심사 변경 사항이다.** 제출한 Security Review 에 `CAMERA` 권한이
없으므로, 추가 전에 보안팀 회신을 받는다. PDA 이식 경로는 권한 추가 없이 해소된다.

## 2. 검토 요청 4건 (선조치로 해소되지 않음)

| # | 항목 | 자체 조치 가능 여부 |
|---|---|---|
| SR-1 | 소스 저장소가 개발자 개인 GitHub 공개 저장소에 위치 | 불가 — 배포 구조 문제 |
| SR-2 | GitHub Releases APK를 앱이 직접 내려받아 자체 설치 (`REQUEST_INSTALL_PACKAGES`) | 불가 — 배포 구조 문제 |
| SR-3 | 설정 접근 인증 값의 빌드 시 주입 전환 | 가능 — BuildConfig + CI Secrets |
| SR-4 | 릴리스 빌드 난독화 적용 | 가능 — 적용 후 회귀 테스트 |

### SR-3 조치 방향

입력 자릿수와 동선은 유지한다. 짧은 입력은 장갑 착용 상태에서 즉시
입력·적용·검증하기 위한 운영상 선택이며, 임계값을 v1.1.77~79에서 일반
화면에서 잠근 뒤 개발자 계층으로 옮긴 구조와 연결된다. 값을 소스에서
분리하는 것만으로 해소되며 현장 운영에 영향이 없다.

## 3. 향후 계획 — PDA 이식

현장 PDA(물류 핸디 터미널)로의 이식을 계획한다. 동일 APK를 사용하며 코드
변경은 없으나, 하드웨어·운용 환경이 달라 착수 전 검증과 보안팀 의견이 필요하다.
Security Review 신청 시 "개발 전 보안팀 의견 청취" 항목으로 함께 요청했다.

| # | 검증 항목 | 내용 |
|---|---|---|
| P-1 | 신호 특성 재검증 | BLE 칩셋이 다르면 동일 거리에서도 RSSI가 달라진다. 본 앱은 `Build.MODEL` 기준 모델쌍 단위로 편차를 학습해 보정하므로, PDA 모델 투입 시 보정값을 새로 축적해야 하며 임계값 재조정이 필요할 수 있다. 현장 실측 검증 예정 |
| P-2 | MDM 배포 | PDA는 MDM으로 앱 설치가 통제되는 것이 일반적이라 자체 업데이터가 동작하지 않을 가능성이 높다. 사내 앱 배포 채널이 사실상 전제 조건이 된다 (SR-2와 직결) |
| P-3 | 공용 단말 | 작업자가 교대로 공유하므로 표시명과 개인의 1:1 대응이 성립하지 않는다. SA-1과 결합 시 개인 식별 가능성이 더 낮아지나, 경보 이력의 개별 작업자 추적은 불가해진다 |
| P-4 | 경보 인지성 | 스피커·진동 모터 사양이 달라 현장 소음 환경에서 인지성 확인이 필요하다. 안전 기능 실효성에 직결 |

기능 자체는 변경되지 않는다. PDA는 UWB 미탑재 기기로 RSSI 단독 판정으로
동작하며, 이는 현재도 UWB 미지원 기기에서 동작하는 방식과 같다.

## 4. 중장기 방향

SR-1, SR-2의 근본 해결책은 사내 이관이다. 금번 심사에서는 방향성 의견만
받고, 승인은 별도 과제로 상신한다.

| 자산 | 현재 | 이관 후 |
|---|---|---|
| 소스 저장소 | 개인 GitHub (공개) | 사내 GitHub |
| CI | GitHub Actions | 사내 CI |
| APK 배포 | GitHub Releases + 자체 업데이터 | 사내 앱 배포 채널 |
| 백엔드 | Firebase RTDB (us-central1) | 사내 인프라 — 데이터 국외 소재 이슈 동시 해소 |
| 서명 키 | GitHub Secrets | 사내 키 관리 |

이관 완료 시 자체 업데이터와 `REQUEST_INSTALL_PACKAGES` 권한을 제거한다.
