# 판정 데이터 기록 안내: 낙상 · 접근 경보

앱은 낙상 판정과 접근 경보 판정이 일어날 때마다 입력값 · 중간값 · 결과를 Firebase `wf11/judge` 에 한 건씩 남긴다.
학습용 정답을 얻으려고 사람에게 두 가지를 묻는다.
- 충격 질문: 감시마다 한 번(넘어짐 판정 충격은 따로) 무엇이었는지(걷는 중 · 뛰는 중 · 폰 내려놓음 · 폰 떨어뜨림 · 충전기 꽂음 · 넘어짐). 구조자가 해제한 경우만 실제로 넘어졌는지
- 거리 질문: 경보가 울릴 때 상대와 거리가 대략 얼마인지

분석은 `scripts/judge-ml/` 에서 한다(그 폴더 README).

## 1. 지킬 것

- **판정은 바뀌지 않는다.**
  - 기록은 판정이 끝난 값을 복사만 한다.
  - 기록이 실패하면 조용히 넘어간다(`runCatching`).
  - 판정 코드(`AlertStateMachine` 의 판정, `UwbRanger` 의 판정 경로, 경보 · 소리 · 확인)는 이 기능 때문에 바뀌지 않았다.
- **측정용 UWB 거리**(아래 6절)는 판정 · 화면 거리 · UWB 학습 · `uwb_probe` 어디에도 쓰지 않는다. 기록에만 남는다.
- **보내기는 잠금 밖에서 한다.** 판정 스레드를 붙잡지 않는다.
- **내보낸 데이터와 분석 결과는 저장소에 넣지 않는다.**
  - 폰 ID(보행자는 쿠코드), 사업장 · 층 · 공정 · 존, `uid` 가 들어 있다.
  - `.gitignore` 에 `scripts/judge-ml/data/` 가 있다.

## 4. 두 질문

### 충격 질문 (알림 → 카드)

- **언제 묻나:** 사고 감시마다 한 번 — 감시를 연 충격, 그리고 규칙이 넘어짐으로 본 충격마다 따로. 같은 감시 안의 다른 넘어짐 아님 충격은 묻지도 않고 약한 진동도 다시 내지 않는다(1.2.26부터). 판정 데이터 기록이 켜져 있을 때만 묻는다. 규칙이 넘어짐으로 보지 않은 충격(1.2.25부터)도 넘어짐과 똑같이 사고 감시(30초 움직임 없으면 확인 창)로 들어가므로 같은 규칙으로 묻는다. 판단 순간에 바로 묻던 `cand` 질문은 없어졌다(예전 기록에는 `close_why` 가 `cand` 인 것이 남아 있다). 확인 창 글은 넘어짐 아님 충격만으로 열렸으면 칩 "충격 감지" · 제목 "폰을 떨어뜨렸나요?", 넘어짐이 하나라도 섞이면 예전 넘어짐 글이다. 넘어짐 아님 충격만으로 연 감시는 폰 움직임(MOVED)도 움직임으로 세어, 확인 창이 폰이 실제로 멈춘 뒤 30초에 열린다(MOVED 는 멈춘 뒤에도 몇 초 더 오므로 마지막으로 움직인 1초 구간의 끝을 멈춘 때로 본다. 충격마다 판정(충격 12초 뒤)까지의 움직임은 그 충격 시각으로 치고 그 뒤 움직임만 센다 — 이어지는 감시의 다음 충격도 같다. 감시 기준 최대 1분, 장비 거치 폰은 장비가 멈출 때까지, 1.2.26부터).
  - 확인 창을 열지 않은 충격(`shut` · `dropped`, 예: 세이프존 · 충전 중): 그 순간. `shut` 는 넘어짐 판정 충격이면 늘 바로 묻고, 넘어짐 아님 충격은 확인 창 · 구조 요청이 열려 있지 않을 때만 바로 묻는다(예: 감시 꺼짐. 열려 있으면 그 창의 닫힘 질문이 맡는다)
  - 지켜보기 시작했는데(`watch`) 40초 뒤에도 확인 창이 안 떴으면(움직여 의심만 끝남, 또는 넘어짐 아님 감시에서 폰이 그때도 움직이는 중): 그때(`moved`). 그때 다른 충격의 확인 창 · 구조 요청(또는 무동작 창)이 열려 있으면 그때(`open`). 창의 닫힘 질문은 창을 연 충격을 묻는다
  - 확인 창을 연 충격: 확인 창이나 구조 요청이 끝난 뒤. 재시작으로 되살아난 감시는 재시작 뒤 첫 충격을 감시를 연 충격으로 본다
  - 질문은 감시마다 한 번(넘어짐 판정 충격은 따로) — 같은 충격(`imp_t`)으로 이미 물었으면(답했거나 알림이 아직 떠 있어도) 다시 묻지 않음(앱 메모리 최근 16건, 재시작하면 비움). 구조자 3버튼 질문은 그대로.
- **알림:** 제목 "방금 충격이 있었어요", 본문 "HH:mm:ss · 무엇이었는지 눌러서 알려 주세요"(충격이 있었던 실제 시각), 버튼 "답하기" 하나. 알림을 누르거나 "답하기"를 누르면 카드가 열린다.
  - 5분 뒤 알림이 사라진다. 알림은 하나(가장 새 질문)이고, 답하지 않은 앞 질문은 남아 있다가 하나에 답하면 다음 카드가 이어서 열린다(5분 안의 것만, 앱 메모리 최근 16건, 재시작하면 비움).
  - 보행 작업자 · 카트 · 관리자 폰은 짧게 한 번 진동한다. 지게차 · EPJ 폰(카트 제외)은 운전 중이라 진동 없이 뜬다.
- **카드:** "방금 무엇이었나요?", "충격 HH:mm:ss · N분 지남". 답 7개(걷는 중 · 뛰는 중 · 폰 내려놓음 · 폰 떨어뜨림 · 충전기 꽂음 · 넘어짐 · 모르겠어요)는 모두 같은 모양이다. AI 확률과 규칙 판단은 보이지 않는다.
  - 바깥을 누르거나 뒤로 가면 답 없이 닫힌다. 5분 안이면 알림에서 다시 열 수 있다.
  - 답하면 `truth`(`act` 칸 포함)로 기록되고 "기록했어요 · 고른 답" 이 뜬다. 5분이 지났으면 "시간이 지나 기록하지 않았어요" 가 뜨고 기록하지 않는다.
- **구조자 확인으로 해제한 경우:** 예전 알림 그대로 "작업자가 실제로 넘어졌나요?"(넘어졌어요 · 아니요 · 모르겠어요, 30분 뒤 사라짐). 앱을 열지 않고 `truth` 로 기록되며 `act` 는 없다.
- **묻지 않는 경우:**
  - 움직임 없음(무동작) 창
  - 감시 종료로 닫힌 창(`off`)
  - 재시작 뒤 복원한 구조 요청(`restore`)

### 거리 질문 (경보 사이드바)

- **언제 띄우나:** 경고 · 위험 경보가 울리기 시작할 때마다 경보 사이드바의 기기 목록 아래에 "지금 상대와 거리는?" 칸이 뜬다(2026-10-30 사용자 결정: 모든 폰 · 항상, 횟수 제한 없음).
  - 칸에는 상대 이름, 경보 시각("14:32:05 울림"), 1초마다 늘어나는 "N초 지남"이 보인다.
  - UWB 로 잰 거리는 답을 흐리지 않게 보여 주지 않는다.
- **답:** 1m 안 · 1~3m · 3~5m / 5~8m · 8~12m · 12~15m / 15m 넘음 · 모르겠어요 (3줄. 1.2.27 전에는 '5m 넘음' 하나였다)
  - 누르면 '기록했어요'가 1초 보이고 닫힌다.
  - 경보 · 소리 · 진동 · 행 탭(30초 확인) · 끝까지 밀기(전체 확인)는 그대로다.
- **묻는 규칙** (`03_service/JudgeAsk.kt`)
  - 경고 이상으로 올라갈 때(안전→경고, 안전→위험, 경고→위험)마다 묻는다. 그대로이거나 내려갈 때는 묻지 않는다.
  - 질문은 한 번에 하나다. 떠 있는 동안 시작된 다른 경보는 묻지 않는다(줄 세우지 않음). 닫히면 같은 상대라도 다음 경보에 다시 묻는다.
  - 경보 시작부터 30초가 지나면 닫힌다. 그 뒤 답은 받지 않는다. 30초 안이면 경보가 먼저 끝나도 칸은 남는다.
- **칸이 안 보이는 경우:**
  - 장비 폰(지게차 · EPJ, 카트 제외)은 멈춰 있을 때만 보인다. 경보 뒤 30초 안에 멈추면 그때 보인다.
  - 사이드바가 화면에 없거나('다른 앱 위에 표시' 권한 없음) 화면이 꺼져 있으면 보이지 않는 것으로 친다.
  - 한 번도 안 보이면 묻지 않은 것이다. 기록도 없다.

## 5. 기록 형식

**경로**: `wf11/judge/<fall|prox>/<사업장 코드>/<yyyyMMdd>/<push id>`
- 사업장 코드가 `^[A-Z0-9_-]{1,12}$` 가 아니면 `NOSITE`
- 날짜는 기록 시각(폰 시계) 기준
- 값이 없는 필드는 빼고 쓴다(null 을 쓰지 않는다)

### 공통 (모든 기록)

| 필드 | 형 | 뜻 |
|---|---|---|
| `v` | 수 | 형식 버전 |
| `k` | 글 | 종류. 낙상은 `cand` · `fall` · `mode` · `truth`, 접근은 `level` · `uwb` · `dist` · `sig` |
| `t` | 수 | 기록 시각 ms (벽시계) |
| `dev` | 글 | 이 폰 ID. 사업장 접두어를 붙인 `alerts` 와 같은 표기 |
| `role` | 글 | 내 역할 이름(`WALKER` · `EPJ` · `FORKLIFT` …). 카트 작업자는 `EPJ` |
| `site` · `floor` · `proc` · `zone` | 글 | 지금 설정 |
| `app` | 글 | versionName |
| `sess` | 글 | 실험 세션(아래 표). 평소는 `field` |
| `uid` | 글 | `auth.uid`. 규칙이 확인한다 |
| `mdl` | 글 | 이 폰 기종(제조사 + 모델, 40자까지, 예 `samsung SM-S918N`). 알 수 없으면 없다. 1.2.27부터 |

`sess` 형식:

| 상황 | 형식 | 예 |
|---|---|---|
| 평소 | `field` | `field` |
| 낙상 실험 (넘어짐) | `test:fall:<이름>` | `test:fall:mat1` |
| 낙상 실험 (넘어짐 아님) | `test:no:<이름>` | `test:no:desk-drop` |
| 접근 거리 실험 | `test:<미터>m:<이름>` | `test:3m:aisle2` |
| 접근 거리 실험 (멀어지며, 묶음) | `test:sweep:<장소>:<묶음>` | `test:sweep:aisle2:a` — 정답은 UWB 거리라 미터를 적지 않는다. 같이 든 폰들은 같은 묶음 글자(10절) |

### 낙상 `cand` — F1

| 필드 | 뜻 |
|---|---|
| `imp_t` | 충격 시각. 판정 시간축 값이라 벽시계가 아니다. `fall` · `mode` · `truth` 와 잇는 열쇠 |
| `ff_ms` | 충격 전 1초 안에서 0.5G 미만이었던 시간 |
| `peak_g` | 충격 1초 창의 최대 G |
| `imp_g` | 이 폰의 충격 기준 G(센서 범위 보정 뒤) |
| `deg` | 충격 전후 자세 변화 각도(모르면 뺌) |
| `post_n` · `post_act` | 2~12초 창의 표본 수 · 활동 창 수 |
| `pre_ok` | 충격 전 자세를 알았는지 |
| `pass` | 후보 결정 통과(FALL) 여부 |
| `why` | 탈락 이유: `post_none` · `post_active` · `posture`. 통과면 `""` |
| `acc` · `acc_t0` · `acc_dt` | (원시 가속도 켜짐) 50Hz `"x,y,z;…"`(mg 정수), 첫 표본 시각(`imp_t` 와 같은 시간축), 표본 간격 ms |

### 낙상 `fall` — F2

| 필드 | 뜻 |
|---|---|
| `imp_t` | `trigMs` |
| `take` | `watch`(의심을 열었다) · `shut`(`fallShut`) · `dropped`(`fallDropped`) |
| `pass` | 규칙 결과: `true` 넘어짐 · `false` 넘어짐 아님 충격(1.2.25부터 이것도 `take` 를 가진다). 예전 기록에는 없다 |
| `zone_in` · `charging` | 충격 때 세이프존 안 · 충전 중 |
| `plug_ago_ms` · `unplug_ago_ms` | 마지막으로 꽂은 · 뽑은 뒤 지난 시간(없으면 뺌) |

### 낙상 `mode` — F3

| 필드 | 뜻 |
|---|---|
| `from` · `to` | `WATCHING` · `CHECKING` · `SOS` |
| `trig` | 그 창을 연 계기 `fall` · `still`. 닫힐 때는 닫히기 전 값 |
| `pass` | `trig` 가 `fall` 일 때만: 규칙 결과(`false` = 넘어짐 아님 충격만으로 연 "폰을 떨어뜨렸나요?" 창). 앱을 다시 켠 뒤 복원한 창 · 구조 요청은 `true` 로 기록 |
| `why` | 닫힌 이유(`to` 가 `WATCHING`): `ack` · `walk` · `charger` · `rescuer` · `sos_cancel` · `auto_1h` · `off`. 복원한 구조 요청은 `restore` |
| `since_ms` | 이전 상태에 머문 시간. `restore` 는 0 |
| `imp_t` | `trig` 가 `fall` 이면 그 충격 시각 |

### 낙상 `truth` — F4 (충격 질문 답)

| 필드 | 뜻 |
|---|---|
| `imp_t` | 그 충격의 시각(`cand` 기록과 같은 기준 값, 기록끼리 잇는 열쇠) |
| `truth` | `fall` · `no` · `unknown` (`act` 가 `fall` 이면 `fall`, `unknown` 이면 `unknown`, 나머지는 `no`) |
| `act` | `walk`(걷는 중) · `run`(뛰는 중) · `put_down`(폰 내려놓음) · `drop`(폰 떨어뜨림) · `charge`(충전기 꽂음) · `fall`(넘어짐) · `unknown`(모르겠어요). 구조자 3버튼 답에는 없다 |
| `by` | `self`(본인) · `rescuer`(구조자 확인으로 해제한 경우) |
| `after_ms` | 본인 답: 답한 시각 − 충격 시각(둘 다 실제 시각). 구조자 답: 창이 닫힌 뒤 답할 때까지 걸린 시간 |
| `close_why` | 창이 닫힌 이유(`mode` 의 `why`). 확인 창 없이 물은 경우 `cand`(1.2.24까지, 규칙 넘어짐 아님) · `shut` · `dropped` · `moved`(지켜보다 움직여 확인 창 없음) |

### 접근 `level` — P2

| 필드 | 뜻 |
|---|---|
| `peer` · `peer_role` | 상대 ID(사업장 접두어) · 역할 이름 |
| `prev` · `level` | 바뀌기 전 · 뒤 단계. `0` 안전 · `1` 경고 · `2` 위험 |

| `off_pl` `off_bc` `off_gg` `echo` | 오프셋 |
| `eff_w` · `eff_d` | 경고 · 위험 문턱(`effWarning` · `effDanger`) |
| `seq` | 최근 10초의 1초 요약 `"ema,kf_vel;…"`, 오래된 것부터 |

P1 값과 코드 변수:

### 접근 `uwb` — P3

| 필드 | 뜻 |
|---|---|
| `uwb_m` | 측정 거리 m |
| `use` | `judge`(판정에 쓰인 표본) · `measure`(측정용 UWB, 기록만) |
| `warn_m` · `dang_m` | 이 짝의 UWB 경고 · 위험 거리 |

| `frame_age_ms` | 같이 실린 P1 값(`rssi` …)이 몇 ms 전 프레임인지. 2초를 넘으면 신호와 거리가 같은 순간이 아니다 |
| `peer` … `seq` | `level` 과 같은 P1 값 |

### 접근 `dist` — P4 (거리 질문 답)

| 필드 | 뜻 |
|---|---|
| `ans` | `lt1`(1m 안) · `1to3` · `3to5` · `5to8` · `8to12` · `12to15` · `gt15`(15m 넘음) · `unknown`. `gt5`('5m 넘음')는 1.2.27 전 기록에만 있다 |
| `alert_t` | 위험 경보 시작 시각(벽시계) |

### 접근 `sig` — P5 (실험 세션 신호)

UWB 없는 폰의 블루투스 신호를 거리(m)로 바꾸는 학습용 기록이다.
- **언제:** 판정 데이터 기록이 켜져 있고 세션 이름이 `test:` 로 시작할 때, 상대마다 1초에 1건. 평소(`field`)는 남기지 않는다.
- **필드:**

| 필드 | 뜻 |
|---|---|
| `peer` … `seq` | `level` 과 같은 P1 값 |
| `frame_age_ms` | 늘 0(이 기록이 프레임 순간의 값이다) |
| `warn_m` · `dang_m` | 이 짝의 UWB 경고 · 위험 거리(지게차가 낀 짝 15 · 8m, 아니면 5 · 3m). UWB 표본이 없어도 붙는다 |
| `uwb_m` · `uwb_use` | 1초 안에 잰 UWB 거리가 있을 때만 |

- **쓰임:** 분석이 같이 든 UWB 폰의 거리(묶음 정답, 10절)를 UWB 없는 폰의 `sig` 행에 붙여 거리 학습에 쓴다(8절 · `scripts/judge-ml`).

```json

 "peer":"WF11-SAFEALERT_DEVICE_C1","peer_role":"EPJ","rssi":-71,"ema":-70.4,"kf_vel":0.3,"eff_w":-87,"eff_d":-74,"seq":"-70.5,0.2;-70.4,0.3;…",
 "frame_age_ms":0,"warn_m":5,"dang_m":3}
```

## 6. 측정용 UWB

- **세션을 여는 때:** UWB 세션은 지금처럼 신호가 -80dBm 보다 강한 상대와만 연다.
- **세션을 유지하는 때:** 이미 열린 세션은 상대가 렉 · 파렛트 뒤로 가서 신호가 약해져도 측정 유지 기준(기본 -95)까지 유지한다.
  - 측정용으로 넘어가는 시점은 예전 코드가 세션을 닫던 시점과 같다.
  - 그 거리는 `uwb` 기록에 `use=measure` 로만 남는다.
- **미리 내려놓기:** 측정 중에 세션 밖 상대가 -85 보다 강해지면 측정을 내려놓는다. 그 상대의 판정 세션이 늦지 않게 하려는 것이다.
- **남는 지연(사용자 승인):** 새 상대가 -85 ~ -80 을 거치지 않고 한 번에 -80 위로 뛰는 경우가 있다(렉 모퉁이에서 불쑥 나온 지게차 등).
  - 그 상대의 UWB 세션은 예전보다 약 0.7~1.6초(+세션 준비 시간) 늦게 열린다.
  - 그동안은 UWB 없는 폰처럼 블루투스 신호로 판정한다.
- **블루투스 광고 꺼짐(300ms):** 상대 한 명 기준으로 예전보다 늘지 않는다.

## 7. 저장 (Firebase)

`database.rules.json` 의 `$site` 아래 `judge`:

```json
"judge": {
  "$kind": {
    "$sc": {
      "$day": {
        "$id": {
          ".write": "auth != null && !data.exists() && newData.exists() && $site.matches(/^[A-Za-z0-9_-]{1,32}$/) && ($kind === 'fall' || $kind === 'prox') && $sc.matches(/^[A-Z0-9_-]{1,12}$/) && $day.matches(/^[0-9]{8}$/)",
          ".validate": "newData.hasChildren(['v','k','t','dev','uid']) && newData.child('uid').val() === auth.uid",
          "acc": { ".validate": "newData.isString() && newData.val().length <= 20000" },
          "seq": { ".validate": "newData.isString() && newData.val().length <= 2000" }
        }
      }
    }
  }
}
```

- **읽기:** 읽기 규칙이 없어 앱은 이 경로를 읽지 못한다. 데이터는 Firebase 콘솔 → Realtime Database 에서 `wf11/judge` 를 JSON 으로 내보낸다.
- **배포:**
  - 규칙은 태그를 푸시할 때 CI(`.github/workflows/release.yml`)가 올린다.
  - 규칙이 올라가기 전에 쓴 기록은 거부된다. 경보 판정은 그대로 동작한다.
  - 콘솔에서 직접 올릴 때는 **파일 전체**를 붙여 넣는다. 일부만 붙이면 나머지 규칙이 지워진다.
- **양 (추정):**

  | 기록 | 양 |
  |---|---|
  | `cand` | 충격 후보마다 1건(원시 가속도 켜면 건당 약 10KB) |
  | `level` | 단계가 바뀔 때, 같은 상대 2초에 1건까지 |
  | `uwb` | UWB 짝마다 1초에 1건(측정용 유지 중 포함), 건당 약 0.5KB |
  | `dist` | 한 폰에서 한 시간에 4건까지 |
  | `truth` · `mode` · `fall` | 사건마다 |

## 8. 분석

`scripts/judge-ml/README.md` 를 본다. 순서는 아래와 같다.
1. **불러오기 · 나누기:** 내보낸 JSON 을 불러오고(`load`), 날짜로 학습 / 실제를 나눈다(`split`).
2. **점검:** 거리 답 점검(`dist-check`), 신호-거리 점검(`rssi-check`).
3. **1차 분류:** AI 1차 분류(`ai-label`) 또는 규칙 1차 분류(`label`).
4. **재분류 · 재학습:** 사람 확인표 → 재분류(`relabel`) → 예시 고르기(`learn`) · 학습 데이터 판단(`ai-judge --on train`).
5. **실제 데이터 평가:** 정답표(`real-sheet`) → `ai-judge --on real` → `eval`. AI 와 지금 앱 판정을 비교한다.

정답은 측정값과 따로 얻은 값만 쓴다.
- **낙상:** `truth` 답, 낙상 실험 세션, 현장 확인표
- **접근:** UWB 거리, `dist` 답, 거리 실험 세션

## 9. 실기에서 볼 것

- **거리 질문 칸:**
  - 위험 경보 때 칸이 뜨는지, 버튼 터치가 행 탭(30초 확인) · 손잡이 끌기로 새지 않는지
  - 30초 뒤 닫히는지
  - 장비 폰은 멈췄을 때만 뜨는지
- **충격 질문 알림:** 짧은 진동 한 번(장비 폰은 무음), 잠금 화면에서 눌렀을 때 카드가 뜨는지, 5분 뒤 사라지는지, 감시 화면의 충격 시각이 실제 시각인지
- **측정용 UWB(폰 두 대 이상):**
  - -80 아래로 내려가도 세션이 유지되는지, `use=measure` 기록이 생기는지
  - 다른 상대가 가까이 오면 내려놓는지

## 10. 실험 하는 법

현장 기록만으로는 넘어짐 정답이 거의 생기지 않고, 접근 기록은 3m 안에 몰린다(2026-10-30 기록 3,149건 중 91%). 두 모델에 모자란 정답을 실험으로 채운다.

**공통**
- 실험 세션 이름 넣기: 개발자 설정 → 맨 아래 '앱 정보'의 버전 글자를 3초 안에 이어서 7번 눌러 고급 옵션을 연다 → '판정 데이터 기록' 아래 '실험 세션 이름' 칸에 넣고 다른 칸을 누른다(저장). 끝나면 칸을 비운다(비우면 `field`). 비우지 않으면 그 뒤 현장 충격까지 실험 정답으로 붙는다.
- 보행 작업자로 감시 중, 충전기 뺀 상태, 세이프존 밖에서 한다. '판정 데이터 기록' · '원시 가속도 함께 기록'은 켜 둔다(기본 켜짐).
- 시도 사이에도 폰은 몸에 지닌다. 창('괜찮으세요?' · '폰을 떨어뜨렸나요?')이 뜨면 바로 [괜찮아요]. 책상에 두고 자리를 비우면 창이 뜨고, 응답이 없으면 구조 요청이 나간다(나갔으면 그 폰에서 바로 해제).
- 충격 질문 알림 · 거리 질문 칸은 무시해도 된다(정답은 세션 이름 · UWB 거리에서 온다).
- '역할별 조기경보 오프셋'은 바꾸지 않는다. 기록마다 그때의 경보 기준(`eff_w` · `eff_d`)과 신호 값이 남아서, 다른 보정값은 나중에 같은 기록으로 계산해 볼 수 있다.
- 끝나면 GitHub Actions '판정 데이터 내보내기' → **Run workflow**(안 누르면 다음 날 자동 내보내기 때 들어간다). 그다음 `scripts/judge-ml` 의 `train` 이 세션마다 '시도 N건'을 보여 준다.

**낙상 (`fall.json`)**
- 안전: 매트 위에서, 혼자 하지 않고, 천천히, 아프면 멈춘다. 매트가 두꺼우면 충격이 후보 기준(2.5G)에 못 미쳐 기록되지 않을 수 있다 — 몇 번 했는지 적어 두고 `train` 의 '시도 N건'과 맞춰 본다.
- 넘어짐: 폰 두 대를 바지 앞 · 뒷주머니에 넣고 세션을 `test:fall:front` · `test:fall:back` 처럼 폰마다 넣는다(한 번 넘어지면 두 건). 한 시도 = 넘어진 뒤 15초 그대로(판정이 충격 12초 뒤) → 일어나 걷기 → 20초 쉬고 다음(한 폰에서 15초 안의 후보는 한 시도로 묶인다). 앞으로(무릎 → 손) · 옆으로 · 뒤로(엉덩방아) 각 5번 이상.
- 넘어짐 아님 `test:no:<이름>`(헷갈리기 쉬운 것 위주): 손 높이에서 바닥에 떨어뜨리고 15초 그대로 → 줍기(케이스 낀 폰), 주머니에 넣고 털썩 앉기, 낮은 턱에서 뛰어내리기 — 각 5번 이상.
- 학습은 넘어짐 · 아님 각 8건부터 돈다. 비교용으로 1/3 을 떼므로 각 12건 넘게 기록되게 한다. 시간을 줄이는 근거로 쓰려면 사람 · 폰 위치 · 바닥을 바꿔 가며 더 모은다.

**접근 거리 (`prox.json`)**
- **묶음:** 한 사람이 같이 드는 폰들(UWB 폰 한 대 이상 + 학습할 UWB 없는 폰)이 한 묶음이다. 같은 묶음 폰은 세션 이름의 묶음 글자가 같다(사람 1 = `test:sweep:aisle2:a`, 사람 2 = `test:sweep:aisle2:b`). 모두 감시 중.
- **정답:** 어떤 두 폰 X(묶음 a) · Y(묶음 b)의 정답 거리 = 같은 장소 묶음 a · b 사이에서 ±1초 안에 잰 UWB 거리(어느 폰이 잰 것이든). 그래서 UWB 없는 폰은 반드시 UWB 폰과 같이 든다. 같은 묶음 폰끼리는 정답이 없다.
- 나란히 서서 시작(UWB 가 붙는다) → 한 사람이 통로를 따라 천천히 멀어지며 2 · 3 · 4 · 5 · 7 · 10m 쯤에서 30초씩 멈춤 → 돌아온다(15m 기준까지 판단할 수 있게 역할과 상관없이 12 · 15 · 18m 에서도 멈춘다. 역할은 신호 세기를 바꾸지 않으므로 역할 조합마다 따로 하지 않는다). 렉 · 파렛트를 사이에 두고 한 번 더, 폰을 손 · 주머니로 바꿔 한 번 더. 한 번 붙은 UWB 는 -95dBm 까지 잰다(6절). 다른 UWB 폰이 가까이 오면 측정을 내려놓으니 멀리 두고, 끊기면 가까이 와서 다시 시작한다.
- `train` 첫 줄 '접근 기록 거리별(UWB)'에서 3~5 · 5~8 · 8~12m 가 각 수백 건이 될 때까지 모은다.
